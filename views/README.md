# views

This folder contains the user-facing outputs of the project.

The `views` layer presents routes, KPIs, outliers, and related scenario data.
It does not contain optimization logic.

## Structure

```text
views/
|-- static/
|   |-- v1/
|   `-- demo_bus_routes_nyc/
`-- application/
    |-- v1/
    |-- v2/
    |-- demo_bus_routes_nyc/
    `-- demo_bus_routes_nyc_single_scenario/
```

## View types

### `static`

Rendered HTML outputs generated by pipelines.

Typical characteristics:

- fixed output per pipeline run
- no client-side data loading
- report-style pages

### `application`

Interactive frontend applications built with HTML, CSS, and JavaScript.

Typical characteristics:

- static frontend code
- data loaded from `JSON` and `GeoJSON`
- filtering and navigation in the browser
- no optimization logic in the view itself

These applications must be served over HTTP because they use `fetch(...)`.

## Local runtime

Application views are intended to run as static files behind a simple local HTTP server.

Example for `demo_bus_routes_nyc`:

```powershell
cd views\application\demo_bus_routes_nyc
python -m http.server 8011
```

Then open:

```text
http://127.0.0.1:8011/html/index.html
```

Check each version-specific README for its exact startup instructions.

## Versioning

Each version folder is self-contained and may have its own data format, entry pages, and README.

This makes it possible to:

- keep older views reproducible
- develop new UI versions in parallel
- avoid breaking previous outputs
